# anti-aistyle-zh × JumpServer 售后口径（整合层）

上游项目：[RichardCao/anti-aistyle-zh](https://github.com/RichardCao/anti-aistyle-zh)（MIT）  
本地副本：`workbuddy/vendor/anti-aistyle-zh/`

本文件是 **Watchdog / WorkBuddy 专用收缩版**：只服务企微售后「回复建议」去 AI 味，不跑小说/提纲/长文 hard fail。

## 场景与强度（按上游 control_modes）

| 项 | 取值 |
|----|------|
| 场景 | 客服口径 / FAQ |
| `rewrite_intensity` | **平衡**（默认） |
| `target_reading_feel` | 更像自然中文 |
| `output_mode` | 最终成稿（不要输出诊断报告） |
| `voice_sample` | 小东 / 小杭企微话术（见 jumpserver-support-style） |

平衡强度含义（摘自上游）：可压重复解释与模板收束，改段首领句；**不新增事实**；不要改成碎口语或故意错字。

## 对「回复建议」的硬约束

1. 第 4 段才是客户可见话术：一句话或一小段，禁止分点罗列；第 1～3 段内部可稍细。  
2. 问什么答什么：纯机制咨询不要加「发版本/截图/复现」尾巴；只有客户明确故障时才引导补充信息。  
3. 第 4 段禁用 AI 排版符：弯引号“”‘’、半角引号、Markdown `**` / 反引号、间隔号·、emoji。  
4. 保真：版本、步骤、URL、报错要求不得编造或删改。  
5. 知识库直链：有高度匹配才带；未命中不贴分类页凑数。  
6. 不做检测器分数优化；不做装人味。

## 优先清掉的残留簇（上游 residual_hotlist 收缩）

- `不是…而是…` / `不只是…更是…` 漂亮二分  
- `真正/本质/核心/关键在于/说到底` 替读者下判断  
- `往往/通常/某种程度上` 无证泛化  
- 客服套话：`希望以上对您有帮助`、`如有疑问随时联系`、`感谢理解与支持`、`我将竭诚`  
- 路标：`首先/其次/最后/综上所述/值得注意的是`  
- 排版 AI 味：满屏 `**加粗**`、emoji 列点、Markdown 标题刷屏  
- 满屏弯引号「」包每个词（偶发引用可留）

## 改写六步（上游改写卡收缩，对短回复）

1. 先删：二次解释、客服套话、升华结尾  
2. 再压：重复功能句  
3. 再换：抽象判断 → 动作/链接/要客户补充的信息  
4. 再补：只用原文已有细节（文档名、URL、版本确认）  
5. 对齐小东/小杭声纹  
6. 自检：还像不像模板？有没有编造？有没有装口语？
